## 🎯 Signal ที่ต้อง action

**สำหรับ builders:**
- ถ้ากำลังตัดสินใจ enterprise agent stack — evaluate "build on platform" (ServiceNow Otto / Salesforce Agentforce / Microsoft Agent 365) vs "standalone framework" (LangGraph / CrewAI) — คำตอบเริ่ม tilt ไปทาง platform เมื่อ customer มี enterprise SaaS install อยู่แล้ว
- Design product เป็น **catalog architecture** ตั้งแต่แรก — separate foundation (connection + auth + knowledge) จาก agent layer เพื่อ reuse ข้าม deployment
- MCP server publish ต้องพร้อมภายใน Q3-Q4 — vendor ที่ปล่อยหลังจากนั้นจะเจอ marketplace saturation

**สำหรับ enterprise:**
- Contract renewal Q3 ต้องมี 3 clause ใหม่: **AI ACV transparency**, **agent portability** (MCP-compatible export), **outcome-based pricing option** (แบบ Salesforce VA AELA precedent)
- Audit MCP compatibility ของ security stack + CX stack ปัจจุบัน — ถาม vendor ว่า MCP server พร้อมเมื่อไหร่, certified กับ Claude/Copilot/Gemini ไหน
- ถาม vendor 3 คำถาม: "deployment ที่ 2-13 ใช้เวลาเท่าไหร่?", "compliance ต้อง approve ใหม่ทุก agent ไหม?", "connector reuse ทันทีไหม?"

**สำหรับ investor/ecosystem:**
- Vertical CX agent = space ที่ funding heavy ใน Q3-Q4 2026 — healthcare care coordination, wealth management onboarding, utility outage, telecom lifecycle เป็น open category
- Standalone workflow automation (Zapier, Make) ต้อง reposition เป็น cross-CRM agent orchestration ก่อน platform-native orchestration จบ moat เดิม
- MCP orchestration middleware — Palo Alto XSOAR, Splunk SOAR, Tines, Torq ต้อง reposition ก่อน AWS/Azure/GCP ปล่อย native MCP gateway (6-9 เดือน window)
