รอบนี้มี 4 เรื่อง เน้น Agentic AI, business use case, และ trend ที่เอามาใช้กับ OpenBridge ได้.

เรื่องแรก.
สวัสดีครับทุกคน วันนี้ Workday ประกาศเรื่องที่น่าจะเปลี่ยน landscape ของ enterprise AI agent ไปอีกรอบ. Workday เปิด Trusted Agent Platform ให้เป็น headless แล้ว แปลง่าย ๆ คือ ลูกค้าสร้าง AI agent ของตัวเอง ด้วย LangChain, Google ADK หรือ Claude Code แล้วเสียบเข้าไปทำงานกับข้อมูล HR และ Finance ของ Workday ได้เลย ไม่ต้องผ่าน UI ไม่ต้องมีคนล็อกอิน. เขาเปิด MCP server มี 275 read tools กับ 54 write tools ครอบทุก workflow ใหญ่. ที่สำคัญคือ model-neutral — รัน Anthropic, Google, OpenAI, Mistral, Nemotron ก็ได้. แต่ที่น่าสนใจกว่าคือ governance — agent ทุกตัวต้องผูกกับ Agent System User แยกจากคน แล้ววิ่งผ่าน OAuth กับ audit trail ชุดเดียวกับ user ปกติ. นี่คือ signal สำคัญ — SaaS ยักษ์ที่คุม data ของ enterprise กำลังเลิกสู้สงคราม UI agent แล้วย้ายตัวเองลงไปเป็น data layer ชั้นล่างที่ agent runtime ของใครก็ได้ต้องมาคุยด้วย. ถ้าคุณสร้าง vertical agent อยู่ นี่คือ surface area ใหม่ที่กว้างมหาศาล — แต่คุณจะต้องยอม Workday เป็น gatekeeper และจ่ายต่อ query. จับตา Salesforce, SAP, Oracle ให้ดี ภายในสองไตรมาสน่าจะมี headless เหมือนกัน.

เรื่องที่สอง.
วันนี้มาคุยเรื่อง Google Cloud ที่เพิ่งปล่อย Gemini Agent — เป็น enterprise agent ที่เปลี่ยนเกมเลย. จุดที่ต่างจากเดิมคือ agent แต่ละตัวจะมี Workspace identity ของตัวเอง — คือ มี Gmail address, มี Calendar, มี Drive folder, มีชื่อใน company directory เหมือนพนักงานปกติ. เพื่อนร่วมงานสามารถ at-mention ชื่อ agent ใน Google Docs ได้แล้วเห็น edit ของมันใน version history. งานยาวได้ 7 วัน — ปิด laptop แล้วมันก็รันต่อ. ข้างในมี 4 ชั้น memory และ agent spin sub-agent ได้ด้วย identity แยกกัน. ที่น่าสนใจกว่าคือ Google ไม่ล็อกให้ใช้ Gemini อย่างเดียว — route ไป Anthropic Claude ได้ตั้งแต่วันแรก. Signal ที่ชัดคือ enterprise กำลังเปลี่ยน mental model จาก agent as feature ไปเป็น agent as coworker — คือเป็น principal ที่ IT ต้อง provision, มี compliance owner, มี offboarding playbook. และ vendor lock-in กำลังย้ายจาก model layer ไปอยู่ที่ identity กับ governance layer ที่ switching cost สูงกว่ามาก. ถ้าคุณเป็น CIO ที่อยู่บน Workspace สองสามไตรมาสข้างหน้าทีมคุณจะเริ่มขอ provision Gemini coworker แน่นอน — HR กับ IT เตรียม policy ล่วงหน้าดีกว่าตามไล่.

เรื่องที่สาม.
มาฟังเรื่อง M&A ที่เพิ่งเกิดและจบในวันเดียว. 13 ตุลาคม Business Insider รายงานว่า Decagon — AI agent startup ที่ทำ customer service automation ที่ valuation 4.5 พันล้านเหรียญ — จ้าง banker มาคุยขายตัวกับ ServiceNow และบริษัทอื่น. ไม่กี่ชั่วโมงต่อมา ประธาน ServiceNow ออกมาปฏิเสธตรง ๆ ว่าไม่มีความสนใจซื้อ. ลูกค้าของ Decagon ที่ public คือ Duolingo, Notion, Hertz, Deutsche Telekom — เป็น enterprise จริงที่ผ่าน procurement แล้ว ไม่ใช่ pilot. เรื่องนี้บอกสองอย่างพร้อมกัน. หนึ่ง — agentic AI startup ที่มี enterprise logo กำลังเริ่มถูกไล่ซื้อ wave M&A ไตรมาส 4 น่าจะหนาขึ้น. สอง — การปฏิเสธอย่างรวดเร็วของ ServiceNow ที่เพิ่งซื้อ 1.1 หมื่นล้านตั้งแต่ปี 2025 คือ signal ของ buyer fatigue. ที่ 4.5 พันล้าน strategic buyer มองว่าสร้างเอง หรือ bolt-on เล็ก ๆ คุ้มกว่า. บทเรียนสำหรับ founder คือ logo ไม่พอ net dollar retention + gross margin ต้องแน่น. บทเรียนสำหรับลูกค้าคือ ถ้าคุณใช้ platform แบบนี้ ขอ data portability กับ pricing lock ไว้ก่อนเลยครับ.

เรื่องที่สี่.
วันนี้มีเรื่องสำคัญสำหรับทุกคนที่ใช้ MCP ใน production. CVE ตัวแรกของ MCP ขึ้น CISA KEV catalog แล้ว — CVE-2026-59822 ที่ LiteLLM MCP gateway. ปัญหาคือเมื่อ auth validation fail handler ไม่ reject request กลับ fallback ไป empty auth object ทำให้ Bearer token ที่สร้างมั่ว ๆ เปิด MCP session ได้ CVSS 8.8 patch ที่ version 1.84.0. ที่น่ากลัวกว่าคือ Wiz honeypot เห็น exploitation attempt ตั้งแต่กรกฎาคม 2 เดือนก่อน CVE จะออก — attacker scan หา endpoint ก่อน defender รู้ตัว. และไม่ได้มาคนเดียว — ชุดเดียวกันมี CVE-2026-59821 ที่เป็น post-auth root RCE และ MCP Python SDK OAuth downgrade issue. ปัจจุบันมี 14 CVE ใน MCP ecosystem รวม + 200,000 exposed MCP servers บน internet. สิ่งที่น่าสนใจคือ pattern — ชั้น auth หายไปเหมือนกันหมด. developer หลายทีมยัง treat MCP server เหมือน internal tool ไม่ใช่ production API. ถ้าคุณ run self-hosted MCP ลง audit auth path เลยวันนี้. ห้าม fallback เป็น silent success. ถ้าทำไม่ไหวย้ายไป managed MCP ของ Cloudflare, Databricks, หรือ Workday ก่อน. และสำหรับ Anthropic กับ Linux Foundation นี่คือ moment ที่ต้องเร่ง reference auth implementation + certification program จริงจัง ไม่งั้นปีหน้ามี CVE แบบนี้อีก 30 ถึง 50 ตัวครับ.
