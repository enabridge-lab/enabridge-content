เรื่องแรก.
ข่าวที่สำคัญที่สุดของสัปดาห์นี้ในวงการ agent infrastructure คือ Linq สตาร์ทอัพซานฟรานซิสโกปิด Series B เก้าสิบล้านดอลลาร์ นำโดย Andreessen Horowitz โดย Ben Horowitz จะเข้าไปนั่งเป็นบอร์ดเอง รายงานจาก Dealroom บอกว่า valuation อยู่ที่ประมาณพันล้านดอลลาร์ ขึ้นมาจาก Series A ยี่สิบล้านเมื่อเดือนกุมภาพันธ์ สิ่งที่ Linq ขายคือการเอา AI agent ออกจาก chat window ไปอยู่ในแอพส่งข้อความที่คนใช้อยู่แล้วทุกวัน Apple Messages for Business, WhatsApp, RCS ลูกค้าไม่ต้องโหลดแอพ ไม่ต้องสมัคร chatbot ของบริษัท agent ก็ส่งข้อความตรงเข้า inbox ปกติได้เลย DoorDash เป็นลูกค้าตัวอย่างที่ให้ลูกค้าสั่งอาหารและจ่ายเงินจบใน SMS conversation เดียว บริษัทอ้างว่าประมวลผ่านข้อความไปแล้วมากกว่าหนึ่งพันล้านข้อความ Thesis เบื้องหลัง deal นี้คือ distribution สำคัญกว่า model quality agent ที่อยู่ใน surface ที่คนใช้อยู่แล้วจะชนะ agent ที่อยู่ในแอพของตัวเอง สำหรับ builder ที่สร้าง agent platform ถ้าคุณยังไม่มี messaging distribution layer เป็น first-class ให้รีบคิดใหม่ สำหรับธุรกิจไทยที่ LINE WhatsApp Facebook Messenger เป็นช่องหลัก คำถามคือ platform ของคุณเชื่อม channel ที่ user ใช้อยู่แล้วได้ลึกแค่ไหน Twilio กับ Sinch ก็ต้องตื่น เพราะ Linq ก็คือ Twilio generation 2 ที่ build on top of infrastructure เดิม caveat คือ valuation พันล้านยังไม่ confirm จากบริษัทเอง และการ text ลูกค้าด้วย agent เป็นดาบสองคม ถ้าใช้เยอะไปเจอ regulatory backlash แน่.

เรื่องที่สอง.
LangChain เพิ่งปิด Series C ที่สามร้อยล้านดอลลาร์ valuation สามพันล้าน นำโดย CapitalG ซึ่งเป็น growth fund ของ Alphabet นักลงทุนใหม่รวม GIC จาก Singapore และ DFJ Growth สิ่งที่สำคัญกว่าตัวเลขคือตัวนำ — การที่ Alphabet เลือกลงใน LangChain แทนที่จะ bundle agent framework ของตัวเองใน Vertex AI บอกว่า Google ยอมรับว่า enterprise ส่วนใหญ่ยังอยู่นอก Google Cloud ตอน build agent และต้องการ neutral layer ก่อน เงินส่วนใหญ่ลงที่ LangSmith ซึ่งเป็น observability platform สำหรับ agent trace eval และ governance ที่รองรับ agent ที่ build ด้วย framework ใดก็ได้ ไม่ว่าจะเป็น LangChain CrewAI LlamaIndex หรือ framework ของตัวเอง LangChain อ้างว่า LangSmith มีทีมติดเงินมากกว่าห้าหมื่นทีม และ Fortune 500 มากกว่าสามร้อยบริษัท valuation โตขึ้นสองจุดสี่เท่าจาก Series B หนึ่งปีก่อน รอบนี้ยืนยันว่า agent observability คือ category ที่ VC คิดว่าจะมี winner ชัดเจน สำหรับ builder ที่ compete ใน observability layer โดยตรง รอบนี้บีบให้เลือก vertical down หรือขายกิจการ สำหรับ CIO ที่ CTO เพิ่งเอา agent ลง production คำถามสำคัญคือถ้า agent ทำผิดวันนี้ debug ได้ยังไง ถ้ายังตอบไม่ได้ ควรตั้ง LangSmith หรือคู่แข่งเป็น baseline ก่อน caveat ตัวเลข revenue LangChain ยังไม่เปิด ประมาณการอยู่ที่ร้อยถึงร้อยห้าสิบล้านต่อปี valuation ratio ยี่สิบถึงสามสิบเท่าถือว่าสูงแต่ไม่สุดโต่งสำหรับ AI infra ปี 2026.

เรื่องที่สาม.
ข่าว vertical agent ที่น่าจับตาของสัปดาห์นี้คือ Model ML สตาร์ทอัพในลอนดอน ปิด Series B สองร้อยห้าสิบล้านดอลลาร์ ที่ valuation หนึ่งพันห้าร้อยล้าน นำร่วมโดย General Atlantic กับ QED Investors บริษัทก่อตั้งโดยสองพี่น้อง Chaz กับ Arnie Englander total funding ตอนนี้อยู่ที่สามร้อยห้าสิบล้านจาก Series A เจ็ดสิบห้าล้านปีที่แล้ว Thesis ของ Model ML ต่างจากค่ายอื่น แทนที่จะสร้าง AI assistant กลางของธนาคาร Model ML เสนอว่าแต่ละ banker แต่ละ analyst แต่ละ consultant ควรมี personal agent ของตัวเอง ที่รู้จัก deal flow สไตล์การเขียน pitch และ lead lists ของเขา agent run ภายใน data ของบริษัท แต่ไม่ถูกเอาไป retrain model ของ vendor ภายนอก สำคัญมากสำหรับ IB consulting PE ที่ client data คือ core asset อีกจุดที่ขายดีคือ model agnostic — platform benchmark ของทุก task แล้ว route ไปหา model ที่ใช้ได้ดีที่สุด เช่น extract table ใช้ Gemini เขียน pitch narrative ใช้ Claude run code ใช้ GPT เงินรอบนี้จะลงที่ engineering กับ customer deployment ลูกค้าปัจจุบันยังไม่เปิดชื่อ บอกแค่ว่าธนาคารและ PE tier หนึ่ง สำหรับ builder ที่กำลังสร้าง agent platform ต้องเลือก early ว่าจะไป personal agent per user หรือ team agent คำตอบไม่มีตายตัว แต่ pivot กลางทางยาก สำหรับธนาคารไทย asset management คำถาม default ของ procurement ปี 2027 จะเป็น vendor นี้ train data ของเราไหม route ไปหลาย model ได้ไหม ถ้า vendor ตอบไม่ชัด ให้ถอยก่อน caveat ยังไม่มี third party case study ยืนยัน productivity gain จริง ทุกตัวเลขมาจากบริษัท.

เรื่องที่สี่.
AT&T เพิ่งพิมพ์ตัวเลขที่ตลาด enterprise agent รอมาทั้งปี ที่งาน AWS Boston วันที่ 14 พฤศจิกายน Luke Corbin ผู้บริหาร AT&T Business ยืนยันว่าบริษัทมี agentic workflow ห้าร้อย workflow อยู่ใน production รัน business process ของบริษัทจริง ตั้ง target ว่าจะทะลุหนึ่งพันห้าร้อย workflow ภายในปี 2027 หรือสามเท่าภายในสิบสามเดือน platform handle มากกว่าหนึ่งล้าน transaction ต่อเดือน และบริโภค AI token สี่สิบห้าพันล้าน token ต่อวัน ซึ่งเป็น scale ที่เทียบได้กับลูกค้าชั้น top tier ของ hyperscaler ตัวเลขนี้ไม่ใช่ pilot แต่เป็น production infrastructure spending ระดับใหญ่ สิ่งที่น่าสนใจคือ architecture ที่ counterintuitive AT&T ไม่ build specialized agent หลายพันตัวแบบที่ IBM Microsoft Imagine Enterprise pitch แต่ maintain agent จำนวนน้อย ที่ execute workflow ผ่าน business logic ที่จัดการแบบ centralized คล้าย microservice pattern ที่ agent เป็น compute layer แต่ business rule อยู่ใน config layer แยกต่างหาก ทำให้ debug ง่าย scale ง่าย audit ง่าย อีกจุดสำคัญคือ human-in-the-loop policy ทุก workflow เริ่มด้วย human review gate human ดู output agent ทุกครั้งจนกว่า accuracy จะถึง mid-to-high 90 เปอร์เซ็นต์ แล้วค่อยปล่อย autonomous สำหรับ builder blueprint นี้คุ้มคัดลอก few powerful orchestrated agent บวก rules engine แยก deployable สำหรับ CFO ตัวเลข 5x ROI ปีแรกเป็นความคาดหวังที่ realistic human gate until ninety percent accuracy เป็น risk management stance ที่เข้าใจง่าย caveat คือทุกตัวเลขมาจากบริษัทเอง workflow ยังไม่ define ชัด อาจรวม workflow ที่ยัง human gated ทั้งหมด.

เรื่องที่ห้า.
Replit เปิดตัว Missions วันที่ 17 พฤศจิกายน เป็น product ใหม่ที่เปลี่ยน UX ของ agent coding จาก คุยทีละข้อความ เป็น ส่งโปรเจกต์ไปทั้งก้อน user กำหนด goal, budget, และ approval gate แล้ว swarm ของ agent หลายตัวทำงานขนาน run ไปจนเสร็จหรือ hit cap สิ่งที่ Replit เน้นหนักที่สุดคือ spending gate ก่อนเริ่ม mission ทุกครั้ง user ต้องตั้ง budget limit เป็น hard cap Replit check spend ทุก step เมื่อถึง cap agent หยุดทันที ไม่มี auto charge เพิ่ม การขอเพิ่มเพดานต้อง human approve ก่อน Mission Agreement คือ structure ที่ user define ก่อนเริ่ม success criteria action ที่ agent ต้อง human approve เช่น contact prospect ส่ง proposal commit product pattern นี้ต่างจาก Claude Code หรือ Cursor ที่ agent run shell command ได้ตลอดเวลาโดยไม่มี structured approval Replit ใช้ Missions เองสร้าง internal product monitoring tool ใน 2 วัน ด้วย budget สามพันดอลลาร์ และอ้างว่าชนะ Claude Code ที่ trace benchmark ห้าเท่า แต่ยังไม่มี benchmark แบบ reproducible ให้ verify ยังไม่เปิดราคา Missions เป็น line item Thesis ของ Replit คือ developer อยาก fire and forget ไปทั้งก้อนแล้วกลับมาดูผลตอนตื่น แต่ fire and forget ที่ไม่มี budget cap คือ recipe disaster ปี 2025 ถึง 2026 มี incident ที่ agent spin loop run inference จน cloud bill พุ่งสิบถึงร้อยเท่า Mission Agreement แก้ปัญหานี้โดยตรง สำหรับ builder การเพิ่ม budget primitive เป็น first class ใน API ตั้งแต่ day one คุ้มลงทุน สำหรับ enterprise procurement ลอก Mission Agreement เป็น template ก่อน onboard agent สำหรับ Cursor Claude Code Antigravity pressure ตอนนี้ไม่ใช่ benchmark แต่คือ governance primitive ต้องมีภายในหกถึงสิบสองเดือน ไม่งั้นเสีย enterprise deal ให้ Replit.
