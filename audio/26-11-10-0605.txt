เรื่องแรก.
Anthropic Engineering เผยแพร่ research post ที่ชื่อว่า The components of agent memory เมื่อวันที่ 6 พฤศจิกายน โดย Lance Martin เป็นผู้เขียน เสนอ pattern ใหม่สำหรับ agent memory ที่แยกเป็นชั้น notes, facts, และ wiki links แต่สิ่งที่คนพูดถึงกันมากคือ offline job ที่ชื่อ Dreams Dreams ทำงานเหมือนการนอนหลับของมนุษย์ agent ไม่ได้รับ request ใหม่ มันไปอ่าน session transcripts ย้อนหลังสูงสุด 100 sessions แล้วเขียน memory store ใหม่ที่สะอาดกว่า ลบ notes ที่ขัดกันทิ้ง merge ข้อเท็จจริงที่ซ้ำ แก้ error ที่หาเจอจากการ cross-reference ตัวอย่างใน paper คือตอน agent เล่น Pokémon Red แล้วจำตำแหน่ง Pokémon Center ผิด dreaming แก้ให้ ตัวเลขที่น่าสนใจคือ wiki-building experiment ที่ dream scaled จาก 2 sessions ไป 128 sessions ดัน accuracy จาก 13 เปอร์เซ็นต์ ไป 48 เปอร์เซ็นต์ Dreams เปิดเป็น research preview job ใน Claude Managed Agents ไม่ได้ open source สำหรับคนสร้าง agent framework นี่คือ pattern ที่ควร study ก่อน implement vector memory แบบเดิม เพราะการแยก memory เป็น layer และมี consolidation job offline เป็น architecture ที่ reduce context pollution และ enable self-correction สำหรับ business ที่ deploy agent อยู่ ถามตัวเองว่า agent ลืมเรื่องผิดบ่อยไหม ถ้าใช่ แปลว่า vendor ของคุณยังอยู่ชั้น prototype ไม่ใช่ production.

เรื่องที่สอง.
Anthropic ยื่น amended S-1 เมื่อวันที่ 2 พฤศจิกายน และตัวเลขที่ shock ตลาดคือ Anthropic ได้ commit ไว้แล้วประมาณ 895 พันล้านเหรียญสำหรับ compute และ infrastructure ผ่าน purchase commitments และ lease agreements เป็นตัวเลขที่สูงสุดเท่าที่ frontier lab เคยเปิดเผย Yahoo Finance เพิ่มเติมว่า 70 พันล้านของ commit นั้นต้องจ่ายภายใน 12 เดือน ข้างหน้า ซึ่ง Anthropic ต้องใช้เงิน IPO บวกหนี้บวก revenue มาจ่าย Q3 revenue อยู่ที่ประมาณ 17 พันล้านเหรียญ เพิ่มจาก Q2 ที่ 11.56 พันล้าน net revenue retention 900 เปอร์เซ็นต์ แปลว่าลูกค้าเดิมใช้จ่ายเพิ่ม 9 เท่าจากปีที่แล้ว ส่วน H1 ขาดทุนประมาณ 80 พันล้าน IPO target สัปดาห์ของ 16 พฤศจิกายน valuation ลงจาก 2 ล้านล้านมาที่ 1 ถึง 1.5 ล้านล้าน CNBC รายงานว่า IPO กำลังเจอ backlash หลัง midterms เพราะประชาชนต่อต้าน data center ที่ใช้ไฟมาก Anthropic ใส่เรื่องนี้ไว้ใน risk factor เอง สำหรับ builder ที่สร้าง agent framework ตอบคำถามว่าจะรันบน frontier lab ของใคร และมี fallback ที่ไม่ degrade performance ไหม สำหรับ enterprise ที่ deploy Claude อยู่ ควร negotiate multi-year contract ตอนนี้ก่อน Anthropic ขึ้นราคาหลัง IPO.

เรื่องที่สาม.
Rivio บริษัท healthtech จากเซาเปาโล ประกาศเมื่อวันที่ 4 พฤศจิกายน ปิด Series A extension ที่นำโดย Valor Capital Group รวมยอด Series A ทั้งหมดประมาณ 33 ล้านเหรียญ post-money valuation 200 ล้านเหรียญ เป็น milestone ที่เร็วมากสำหรับ startup ที่ก่อตั้งแค่ปีเดียว สิ่งที่น่าสนใจคือ product และ business model Rivio ไม่ขาย SaaS tool ให้โรงพยาบาลใช้เอง แต่ขายเป็น managed service ที่รัน agent บวก specialist staff ของตัวเอง ทำ audit billing ข้าม 5 fronts ของ revenue cycle ก่อน claim ถึง health plans ลูกค้าจ่ายเฉพาะเวลา recover เงินได้ pay-on-results ไม่ใช่ subscription รายเดือน Rivio ใช้งานใน 13 เครือโรงพยาบาลรวม Albert Einstein ซึ่งเป็นโรงพยาบาลเอกชนใหญ่สุดของบราซิล Sírio-Libanês São Camilo และ Oswaldo Cruz pattern นี้มีมาแล้วใน BPO แต่ margin บางเพราะใช้ human labor Rivio เปลี่ยน unit economics โดยใช้ agent แทน human ส่วนใหญ่ margin สูงขึ้น scale ได้ไว ถ้า model นี้ work จะ copy ไปได้ทุก industry ที่มี high-leverage back-office work insurance claims tax compliance procurement HR ops สำหรับคนสร้าง agent framework โฟกัสที่ domain เฉพาะ pricing model ควร align กับ outcome ลูกค้า บริษัทไทยที่คิดจะ outsource back-office ให้ AI ตอนนี้มี benchmark แล้ว ถาม vendor ว่ายอม pay-on-results ไหม ถ้าไม่ แสดงว่า vendor ยังไม่มั่นใจใน product ตัวเอง.

เรื่องที่สี่.
Anthropic เปิด Message Threads เป็น public beta บน Messages API เมื่อวันที่ 2 พฤศจิกายน แก้ปัญหา latency ใหญ่สุดของ long-running agent คือการส่ง full conversation history ทุก turn Developer เพิ่ม thread parameter ครั้งแรกส่ง full conversation ครั้งถัดไปส่งเฉพาะ new message กับ ID ของ previous response ผลที่บริษัทรายงาน median time to first token ลดลงประมาณ 35 เปอร์เซ็นต์ สำหรับ request ที่มี context 500,000 ถึง 1 ล้าน tokens Claude ยังอ่าน full conversation ทุก turn ใช้ token เท่าเดิม แต่ server-side caching ทำให้ไม่ต้อง re-parse ทั้งหมด detail ที่ควรรู้ thread หมดอายุ 5 นาทีหลัง request สุดท้าย content เก็บใน memory ไม่ลง disk ไม่ compatible กับ zero data retention และไม่ใช่ HIPAA ready feature เปิดเป็น default ใน Claude Code แล้ว รองรับผ่าน native platform plus AWS plus Microsoft Foundry plus Google Cloud 35 เปอร์เซ็นต์ TTFT ลดลงฟังดูเป็น incremental แต่ถ้า agent รัน 100 turn ใน task เดียว compound เป็นหลายนาที signal ที่สำคัญกว่าคือ Anthropic กำลัง optimize infra สำหรับ agent workload ไม่ใช่ chat สำหรับคนสร้าง agent framework ควร wrap Message Threads เข้าใน abstraction ตัวเองก่อน developer เขียน thread handling เอง ถ้า business ของคุณ deploy agent บน Claude API ให้ถามทีม engineering ว่า migrate ไป Message Threads แล้วหรือยัง ถ้ายัง นั่นคือ low-hanging improvement.

เรื่องที่ห้า.
OpenAI มี signal สามตัวในสัปดาห์นี้ที่บอกการ reposition หนึ่ง Greg Brockman ให้ interview กับ WSJ ยอมรับว่าครึ่งปีแรก OpenAI struggled ต้องกลับไป fix Codex, agent reliability และ enterprise sales pipeline จนช่วง Q3 เริ่มมี traction สอง จ้าง security firm Hacktron ทำ joint testing focus ไปที่ agent-to-third-party integration ซึ่งเป็น surface ที่ MCP vulnerability หลายตัวโดนปี 2026 สาม OpenAI positioning Frontier เป็น cross-company agent layer plus AI superapp for work ตั้งใจชน Microsoft Agent 365 และ Google Gemini Enterprise Frontier เปิดตัวตอน 2 กรกฎาคม 2026 พร้อม 2.5 พันล้านเหรียญ funding และทีม 6,000 engineer จนกระทั่งสัปดาห์นี้ OpenAI pin positioning ชัดว่า ChatGPT for enterprise ไม่พอ ต้องเป็น Frontier ที่ sits above every SaaS app การยอมรับของ Brockman ว่า struggled ครึ่งปีแรก ปกติ CEO ไม่ public แพ้ แปลว่า OpenAI มั่นใจว่า Q3-Q4 recovery ใหญ่พอจน admit ปัญหาเก่าได้ Hacktron hire คือ shift จาก model safety ไป system safety ซึ่งเป็น practical security ที่ enterprise CIO ปวดหัวกว่า alignment theory สำหรับ business ที่ใช้ ChatGPT Enterprise ให้เตรียมคุยกับ OpenAI account team เรื่อง Frontier migration path คาด sales push หนักขึ้น Q4 Q1 2027 Enabridge หรือ reseller ไทยที่ขาย OpenAI ต้อง build Frontier capability ก่อน competitor.
